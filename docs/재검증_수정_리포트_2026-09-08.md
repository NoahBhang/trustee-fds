# trustee-fds 재검증·수정 리포트

**작성일:** 2026-09-08

**기준 커밋:** `43d52b4c3ee46c9222465cff6d8818f0060dab14`

**범위:** 코드·룰·합성 데이터·골든파일·문서의 정합성 개선

## 결론

초기 재검증에서 재현된 기술적 결함은 수정했다. 골든파일 검증의 거짓 음성,
확인된 채무감소의 Value In 누락, 과다변제 초과분 누락, 거래 링크 순환·중복 미검출,
잘못된 숫자·날짜의 결측 오인, 미승인 룰의 무표시 실행이 더 이상 조용히 통과하지 않는다.

다만 법률 전문가 검토와 실사건 외부 검증은 코드 수정으로 대신할 수 없다. 현재 결과는
여전히 연구·포트폴리오 단계이며, 실제 사건용 `production` 승인을 의미하지 않는다.

## 수정 내역

### 1. 골든파일 검증 강화

- 기대·실제 transaction ID 집합을 양방향으로 비교한다.
- 중복 기대 ID와 중복 실제 결과 ID를 실패로 처리한다.
- 기대값이 존재하는데 실제 소급기간·우선순위가 `None`인 경우를 검출한다.
- 도달 단계, 후보 여부, 소급기간, 우선순위, Value Out/In, 대가비율, 신호,
  플래그, 탈락 사유를 정확 대조한다.
- `target_stage` 미도달도 CLI exit code 1로 CI를 실패시킨다.
- 기존 CSV에서 쉼표가 포함된 설명이 열을 깨뜨리던 행을 정상 인용했다.

### 2. 경제 실질 계산 수정

- `liability_reduction`을 확인된 채무감소로서 Value In에 포함했다.
- 정상 채무변제는 기존처럼 다른 조문 검토로 라우팅한다.
- 과다변제는 `지급액 - 실제 채무감소액`의 양수 부분만 Value Out으로 분리한다.
- T027은 기존의 비후보에서 30,000,000원 초과변제 후보로 복원됐다.
- 계약상 대가가 있으나 지급이 미확인된 경우 `payment_unverified`만 표시하고,
  `no_verified_consideration`을 중복 표시하지 않는다.
- `회수 기대액` 표현을 확률을 포함하지 않는 `순출연 추정액`으로 고쳤다.

### 3. 입력·그래프 무결성 강화

- 날짜, 유한한 숫자, 금액 범위, 비율 범위, Y/N 및 열거값을 로드 시 검증한다.
- 형식 오류를 정상적인 결측으로 바꾸지 않고 CRITICAL로 처리한다.
- CRITICAL이 있으면 결과 산출 전에 실행을 중단한다.
- 중복 `transaction_links.link_id`, 중복 edge, 다중 노드 순환을 검출한다.
- 근거가 없는 probable/verified 자금흐름 링크를 CRITICAL로 처리한다.
- CLI뿐 아니라 엔진을 직접 호출해도 CRITICAL 입력에서는 판정을 거부한다.

### 4. 특수관계 사실 모델 보강

- 혈족·인척은 `kinship_degree`를 확인해 각각 8촌·4촌 범위를 적용한다.
- 직원은 직함만으로 분류하지 않고 `financial_dependency`와
  `shared_livelihood` 사실을 사용한다.
- 개인 채무자는 단독 지분, 관계인 합산 지분, 사실상 지배력을 구분한다.
- 법인 채무자의 계열회사는 단순 30% 근사가 아니라
  `affiliate_status_verified` 사실로 판정한다.
- 필요한 사실이 없으면 `related`를 추정하지 않고 `verify`로 남긴다.

### 5. 표현과 운영 통제

- 자금 링크 신호를 `funds_circled_back`에서 `related_party_fund_flow`로 변경했다.
  현재 스키마가 동일 자금의 환류까지 증명하지 못한다는 점을 이름에 반영했다.
- 룰 메타데이터와 상태값을 검증하고, CLI 시작 시 비-production 상태를 표시한다.
- 직접 스크립트와 패키지 진입점(`python src/cli.py`, `python -m src.cli`)을 모두 지원한다.
- 동작 변경에 맞춰 주 룰을 0.2.0, 특수관계 룰을 0.4.0으로 올렸다.
- NOTICE, README, 링크 설계 기록을 현재 구현과 일치시켰다.

### 6. 후속 코드 리뷰 반영

- 종료 코드는 비트마스크가 아니라 상호 배타적인 상태 코드임을 바로잡았다.
  CRITICAL 입력은 골든 대조 전에 2로 종료하고, 대조 실패는 1로 종료한다.
- 과다변제 결과에는 실제 지급액·실제 채무 감소액·초과분을 별도로 출력한다.
  초과분 분석 행의 `Value In=0`이 정상 상환분의 부재를 뜻하지 않음을 명시했다.
- `suspension_date_confirmed=N`인 지급정지일은 후보 누락 방지용 잠정 기준점임을
  CLI 첫머리에 경고한다. 자동 민감도 비교는 여전히 로드맵 6 과제다.
- 거래 링크는 첫 순환에서 멈추지 않고 모든 순환 구성요소를 보고한다.
- 위 출력 변경에 맞춰 주 룰 버전을 0.2.1로 올렸다.

## 자기점검과 남은 한계

1. **법률 검토는 미완료다.** `art391-4-gratuitous`는 `draft`, 특수관계 룰은
   `spec_verified`다. 코드가 이 상태를 숨기지는 않지만 법률 전문가의 승인으로
   바꿔 적을 수는 없다.
2. **외부 타당도는 미검증이다.** 모든 샘플이 합성 자료이므로 실제 사건에서의
   금액가중 재현율, 오탐 검토시간, 전문가 간 일치도는 알 수 없다.
3. **미확정 지급정지일의 자동 민감도 비교는 미구현이다.** 기본 실행은 누락 방지를
   위해 미확정일도 잠정 기준점으로 사용하고 이를 경고하지만, 미특정·대체일 결과를
   한 번에 산출해 비교하는 기능은 아직 로드맵 6에 남아 있다.
4. **복수 관계 모델이 남아 있다.** party 당 단일 `relation_type`이라 서로 다른
   유효기간을 가진 배우자·임원 등 복수 관계를 완전하게 표현하지 못한다.
5. **자금 동일성은 증명하지 않는다.** 추적 금액·계좌 명의·원거래 대금과의 대응이
   없어 `related_party_fund_flow`는 조사 단서다.
6. **가치평가 한계가 남아 있다.** 보증채무의 액면/기대가치, 포기 채권의 액면/
   회수가능 가치, 복수 상대방별 가치 배분은 별도 모델링이 필요하다.
7. **채무감소의 독립 검증 필드가 없다.** 현재 `liability_reduction`은 증빙으로
   확인된 실제 감소액이 입력된다는 전제다. 출처 종류와 검증 상태를 별도 필드로
   분리하는 것은 후속 스키마 과제다.
8. **골든파일은 독립 정답이 아니다.** 현재 엔진 출력에서 출발해 수동 검토한 회귀
   계약이며, 설명 플래그의 순서까지 고정한다. 구현 회귀에는 강하지만 법률적 타당성의
   독립 검증 가치는 낮고, 정당한 출력 변경도 기대값 갱신을 요구한다.

따라서 수정 후 평가는 **기술적 PoC 완성도는 상승했지만, 실사건 적용 승인은 여전히
보류**다. 다음 검증 단계는 독립된 법률 전문가가 익명화 사례를 블라인드 라벨링하고,
불일치 사례를 합의 판정한 뒤 금액가중 재현율과 검토 부담을 측정하는 것이다.
